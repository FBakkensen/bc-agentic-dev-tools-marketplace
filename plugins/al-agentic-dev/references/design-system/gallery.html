A Linear-style component vocabulary the al-agentic-dev plugin consumes when generating event-model.html, architecture.html, and tasks.html for Business Central features.

Every example below shows the rendered component on the left and the canonical HTML source on the right. The agent reads source; humans read pixels.

Heading scale + body

Architecture

Catch item charge allocation mismatches at posting time before the invoice posts, surface the cause inline on the document, and produce a deterministic audit trail tying each allocation back to its source line.

Module boundaries

Three modules cooperate under a strict R → P → W discipline. Charge Validation reads, Allocation Resolver processes, and Posting Subscribers writes through the existing Sales-Post codeunit.

Read → process → write

Reads sit on the released document. Processing builds an in-memory allocation graph. Writes go through the BaseApp posting routine — no direct table writes from feature code.

Brownfield touchpoints

Event subscribers on OnAfterCheckSalesDoc and OnBeforePostSalesDoc. Both fire from Sales-Post.

Inline code & code block

The subscriber lives on Sales-Post codeunit 80. It receives the prepared Sales Header and delegates to Charge Validation.

[EventSubscriber(ObjectType::Codeunit, Codeunit::"Sales-Post",
                 'OnAfterCheckSalesDoc', '', false, false)]
local procedure HandleCheckSalesDoc(var SalesHeader: Record "Sales Header")
var
    Validator: Codeunit "Charge Validation";
begin
    if not Validator.Validate(SalesHeader) then
        Error(Validator.GetLastMismatch());
end;

Marginalia aside

Floats into the right margin on wide viewports; collapses inline with a left rule on narrow.

Posting Subscribers is the only module that writes; everything else reads or processes. This is the boundary that protects the BaseApp posting routine.

Reads sit on the released document. Processing builds an in-memory allocation graph. Writes go through the BaseApp posting routine — no direct table writes from feature code. The discipline matters because every direct table write from feature code is a future merge conflict against a base table extension.

Callouts

Four variants. Use the icon glyph in the source so it survives any CSS strip.

Note · Warning · Blocked · Replan

i

Note

The validator is pure — it never reads outside the in-memory graph built by Allocation Resolver.

!

Warning

Subscribers on OnBeforePostSalesDoc can run inside a transaction. Do not call long-running validators here.

×

Blocked

Awaiting decision on whether to extend existing Allocation Account Entry or introduce a new Item Charge Allocation Ledger Entry table.

↻

Replan

Replan trigger fired during refine. Original test only covered equality; refined to cover both inequality directions.
