Sales Document Posting: Item Charge Allocation Validation

A user-facing journey for catching item charge allocation mismatches at posting time. Two roles cooperate across four event chains; the Posting Engine takes the document the moment the Order Processor hands it over.

Roles

Two roles. The Order Processor is a human; they release the document and trigger posting. The Posting Engine is a BC service; once posting starts, it owns the document.

Branch on validation failure

If Item Charge Allocation Validated reports a mismatch, the chain loops back to Released Sales Order Card with allocation breakdown surfaced inline. The Posting Engine releases the document; no partial state is written.
